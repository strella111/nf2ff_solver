# Дальняя зона (расчёт ДН) — FarZone

Автономная утилита расчёта диаграммы направленности (ДН) в **дальней зоне** из
данных планарного сканирования ближнего поля (преобразование NF→FF). Выделена из
основного проекта автоматизации в самостоятельную программу.

## Что делает
- Загружает папку с результатами режима «Измерение лучей АФАР».
- Показывает **ближнее поле в 2D** — карту измеренной амплитуды (дБ) или фазы (°)
  по апертуре; доступна сразу после загрузки, до всякого пересчёта.
- Либо открывает **отдельный файл** измерения (`Открыть файл`) — для разового
  пересчёта; роль «луча» играет имя файла, а шаг `dx`/`dy` и прочие параметры
  задаются вручную (scan_params.json не требуется).
- Считает сечения ДН в дальней зоне (азимут/угол места) методом спектра плоских
  волн (2D-БПФ + интерполяция, Ludwig-2).
- Показывает совмещённый график: амплитуда (дБ, левая ось) и фаза (°, правая ось),
  4 трассы Az/El × ампл./фаза, каждую можно скрыть.
- Считает метрики: максимум, положение Az/El, ширина ДН (−3 дБ), УБЛ Az/El, фаза
  в максимуме, заданный угол α/β (по номеру луча).
- Фоновый расчёт всех выбранных лучей/частот с прогрессом и отменой; результаты
  кэшируются — переключение лучей/частот мгновенное.
- Чтение Excel тоже идёт в фоне: окно не «замирает», внизу видно, какой файл и
  какая частота читаются, и загрузку можно прервать кнопкой «Отмена».

## Формат входных данных
Папка должна содержать:
- `Beam№<N>.xlsx` — по файлу на луч (амплитуда/фаза по сетке X×Y для каждой частоты);
- `scan_params.json` — параметры скана (список лучей, частот, координаты, шаги
  `step_x`/`step_y` в см).

Шаг сканера трактуется в **сантиметрах** (как в исходном MATLAB-инструменте) и
переводится в метры (×1e-2).

Можно открыть и **один** `Beam№<N>.xlsx` без папки и `scan_params.json`
(кнопка `Открыть файл` или перетаскивание файла в окно) — тогда частоты берутся
из самого файла, а шаг `dx`/`dy` вводится вручную в окне параметров.

## Установка и запуск
Требуется **Python 3.10+** (проверено на 3.13) и Windows (используется PyQt5).

```bat
pip install -r requirements.txt
python main.py
```

Зависимости: `numpy`, `PyQt5`, `pyqtgraph`, `openpyxl`, `loguru`, `QtAwesome`.

## Сборка в .exe
```bat
python build.py            REM собрать текущей версией
python build.py 1.2.0      REM задать версию и собрать
python build.py --clean    REM пересоздать .venv с нуля
```
Скрипт создаёт изолированное окружение `.venv`, ставит в него зависимости
(глобальный Python не трогается) и собирает один файл `dist\FarZone-<версия>.exe`
по `FarZone.spec` (в spec включены `theme.qss`, набор иконок `styles/glyphs`
и шрифты `qtawesome`). Иконку самого exe готовит `build_icon.py` из
`far_zone/styles/glyphs/app.svg`.
Версия берётся из `far_zone/__init__.py` (`__version__`) и показывается в
заголовке окна.

Вручную (в активированном venv):
```bat
pip install -r requirements.txt
pyinstaller --noconfirm --clean FarZone.spec
```

## Параметры пересчёта
Окно «Параметры пересчёта» (кнопка «Параметры…»):
- **Диапазоны и шаг** Az/El (град).
- **Шаг X (dx)** / **Шаг Y (dy)** — шаг сканера, см (берутся из `scan_params.json`).
- **Точек БПФ** — множитель дополнения нулями (×2/×4/×8/×16). Главный рычаг
  точности: чем больше, тем плотнее k-сетка и тем меньше влияет метод
  интерполяции. Абсолютный размер БПФ = `next_pow2(отсчётов) × множитель`.
- **Интерполяция** — Бикубическая / Кубический сплайн / Билинейная.
- **Модуль (abs)** — когда брать модуль амплитуды: «После» (интерполируется
  комплексный спектр, затем модуль — точнее у нулей) или «До» (модуль до
  интерполяции — как в MATLAB).

Выбор запоминается между сессиями.

## Окно
Верхняя панель — тулбар: источник данных, переключатель вида, наложения,
навигация по лучу и частоте. Если ширины не хватает, лишнее уезжает в меню
переполнения справа, а не обрезается. Внизу статусная строка: слева текущий
источник (длинное имя сокращается многоточием, полный путь — в подсказке),
справа полоса прогресса и «Отмена» — место под них есть всегда, поэтому
график больше не прыгает при загрузке.

Панель метрик и область графика разделены **сплиттером**: ширину можно тянуть,
она запоминается между сессиями вместе с геометрией окна.

## Два вида: ближнее поле и дальняя зона
Переключаются кнопками в верхней панели.

- **Ближнее поле** — активно сразу после загрузки. 2D-карта по апертуре, сверху
  переключатель «Амплитуда / Фаза». Оси в сантиметрах: в режиме папки берутся из
  `scan_params.json`, в режиме одиночного файла строятся по шагу `dx`/`dy` из
  окна параметров. Инструменты слева: подгон масштаба, отметка максимума,
  равный масштаб X/Y (по умолчанию выключен), экспорт PNG/CSV. Под картой —
  перекрестие и значения амплитуды и фазы в ближайшем узле сетки.

  **Отметка максимума** ставит крест в точку максимума амплитуды и подписывает
  её значение и координаты; на карте фазы отметка остаётся в той же точке —
  интересна фаза в максимуме, а не максимум самой фазы. Слева в метриках рядом
  с максимумом показываются его координаты, размах амплитуды и размах фазы.

  Отрисовка и работа мышью — как в режиме «Измерение лучей АФАР» основного
  проекта: неизмеренные точки прозрачны, **ЛКМ** тянет вид, **ПКМ** меняет
  масштаб по двум осям, **колесо** зумит, **двойной клик** по карте подгоняет
  вид под измеренные точки. Шкала справа правится перетаскиванием ручек либо
  вводом значений по двойному клику (там же переключается автомасштаб). По
  умолчанию амплитуда — авто по данным, фаза — фиксированные −180…180°.

  **Палитры разные для амплитуды и фазы.** Амплитуда — `turbo` (синий →
  красный), как в скане лучей. Фаза — **циклическая** `CET-C1`: фаза
  замыкается, −179° и +179° физически почти одно и то же, а `turbo` красил их
  в синий и красный (разрыв между концами шкалы — 74 из 255), из-за чего на
  карте появлялся скачок там, где его нет. У `CET-C1` концы шкалы совпадают
  (разрыв 2 из 255), и ни один её цвет не подходит к белому ближе 122 из 255 —
  поэтому измеренные точки не сливаются с непромеренными (они прозрачны).
- **Главные сечения ДН** — засерена, пока не было пересчёта. Кнопка
  «Пересчитать…» открывает параметры и запускает расчёт; после него вид
  переключается на дальнюю зону сам.

Луч и частота переключаются общими комбобоксами и стрелками: в ближнем поле
доступно всё загруженное, в дальней зоне — только рассчитанное (пересчёт часто
идёт по части лучей). Выбор сохраняется при переключении вида. Новая загрузка
снова гасит дальнюю зону — прежний расчёт к новым данным не относится.

Рядом с номером луча всюду показываются его **углы отклонения** α/β (α —
азимут, β — угол места) — в списке выбора, в заголовке графика и в панели
метрик. В режиме одиночного файла луча нет, поэтому углы не выводятся.

Справа от стрелок — **порядок перебора лучей**; он же задаёт порядок строк в
пакетном экспорте метрик и запоминается между сессиями:
- **по номеру** — как лучи пронумерованы;
- **по азимуту α** — все углы места при одном азимуте, затем следующий азимут;
- **по углу места β** — все азимуты при одном угле места, затем следующий.

Нумерация лучей идёт растром (`beam = α_index · 117 + β_index + 1`), поэтому
«по номеру» и «по азимуту» дают один и тот же ряд; «по углу места» — тот же
набор, но обойдённый поперёк. Группировка работает по тому набору, что реально
загружен (обычно десятки лучей из 5967), полная решётка не требуется; при
сгруппированном порядке ведущий угол в списке идёт первым, чтобы граница между
группами была видна. В режиме одиночного файла выбор порядка скрыт.

Слева под метриками ближнего поля — блок **«Параметры скана»**: файл текущего
луча, область и шаг сканирования, список частот, настройки PNA и синхронизатора.
Строки берутся из `scan_params.json` и появляются только те, для которых там
есть данные; если параметров нет вовсе (одиночный файл), блок скрыт целиком.

## Работа с графиком (дальняя зона)
- **Тумблеры трасс** (справа сверху) — скрыть/показать любую из 4 трасс.
- **Как читать 4 трассы**: тон = плоскость (Az — индиго, El — зелёный),
  начертание = величина (**амплитуда сплошная**, **фаза штриховая и светлее**).
  По штриховке сразу видно, к какой оси относится кривая: сплошные читаются по
  левой оси (дБ), штриховые — по правой (°). Правая ось намеренно нейтрального
  цвета: трасс на ней две, и красить её в цвет одной из них — значит
  утверждать неверное соответствие.
- **Маркеры**: «+ вертикаль»/«+ горизонталь» (значения на пересечении с трассами);
  ПКМ по линии — удалить, двойной клик — ввести точное значение. Иконка кнопки
  в панели слева покрашена в цвет линии, которую она ставит. **Каждая линия
  подписана своим именем** — `V1 · 12.34°`, `H1 · -3.00 дБ`, `Макс · 1.47°`:
  имена в таблице бесполезны, пока линии на графике безымянные.
- **Таблица маркеров** под графиком — строка на маркер, как в анализаторах
  цепей: позиция, значение по каждой трассе и **своя колонка `Δ` у каждого
  главного сечения** (`Δ Az`, `Δ El`). Что в `Δ`:
  - горизонтальный маркер — **ширина по его уровню** для этой трассы, между
    пересечениями **вокруг максимума**. Ширины у сечений разные (в Az апертура
    длиннее — луч уже), поэтому дельт столько же, сколько амплитудных трасс;
    считать «крайнее минус крайнее» нельзя: ниже уровня боковых лепестков
    пересечений больше двух, и получился бы размах по лепесткам, а не ширина;
  - вертикальный маркер — **разница с опорным** (`V2 − Макс`), то есть сразу
    УБЛ в дБ. Опорный — маркер максимума, а если его нет, первый вертикальный;
    в его строке стоит «опора».

  Заголовок и строка помечены чипом с цветом и начертанием линии. Клик по
  строке подсвечивает линию на графике (сплошная и толще), клик по линии —
  выделяет строку. `Del` убирает маркер (попасть в линию мышью труднее),
  `Shift+C` — все. Пока маркеров нет, таблица места не занимает. Наведение на
  ячейку показывает подробности: полный список пересечений, чем считалась Δ.
- **Двойной клик по полю** — автомасштаб.
- **Поиск максимума** (`M`) и **локальных максимумов** (`Shift+M`).
- **Нормировка** (`N`), **маска УБЛ** (годен/не годен по заданному пределу).
- **Горячие клавиши**: `V`/`H` — маркеры, `Shift+C` — убрать все, `A` —
  автомасштаб, `←/→` — луч, `PgUp/PgDn` — частота.
- **Экспорт**: PNG/CSV графика; пакетный экспорт метрик всех лучей×частот в
  Excel/CSV. CSV пишется **колонками** (столбец угла на каждую сетку, дальше
  трассы): строками при мелком шаге по углу упирались в предел Excel в 16384
  столбца и хвост трассы молча пропадал.

## Заметки по математике
- Интерполировать корректнее **комплексный** спектр, затем брать модуль («После»):
  модуль имеет изломы в нулях, на которых сплайн даёт выброс.
- **Главный рычаг точности — число точек БПФ** (zero-padding). При достаточном
  значении (×8…×16) все методы интерполяции сходятся к одной (истинной) кривой —
  истинная интерполяция спектра дискретного БПФ это sinc/Dirichlet, а полиномы
  лишь приближают её.
- **Соответствие расчёту MATLAB** (`interp2(...,'spline')` по `abs(fx')`):
  **Кубический сплайн + ×4 + «До»**.
- Физически самый корректный режим: **Кубический сплайн + «После» + ×8**.
- **Действительное окно углов.** Спектр плоских волн определён только в окне
  k-сетки (`|kx| ≤ π/dx`, `|ky| ≤ π/dy` — предел Найквиста по шагу сканера). За
  ним интерполятор «прижимается» к краю и даёт постоянную «полку». Такие углы
  обрезаются (NaN, линия рвётся). Граница: `sin(θ_max) = λ/(2·d)`, `λ = c/f`,
  `d = dx` (азимут) / `dy` (угол места). Если `d ≤ λ/2` — виден весь сектор ±90°.

## Устранение неполадок
- **Не открывается / пустой график темы** — проверьте, что рядом с
  `far_zone/app_style.py` есть папка `styles/` с `theme.qss`, `icons/` и
  `glyphs/`.
- **Пустые кнопки без иконок** — не доехала папка `far_zone/styles/glyphs`
  (в `FarZone.spec` она входит в `datas` целиком); пересоберите
  `python build.py --clean`. Проверить набор без запуска окна:
  `python -m unittest discover -s tests`.
- **Лог программы** — `%LOCALAPPDATA%\FarZone\logs\farzone_<дата>.log`.
  Собранный exe идёт без консоли, поэтому ошибки писать больше некуда.
- **«Не удалось загрузить данные из папки»** — в папке должны быть `Beam№*.xlsx`
  и `scan_params.json`.
- **Долгое открытие файлов** — это нормально: разбор `.xlsx` занимает секунды и
  больше. Полоса внизу показывает текущий файл/частоту; пока полоса «бегущая»,
  идёт разбор книги целиком (долю на этом этапе оценить нельзя). Открытие можно
  прервать «Отменой», окно при этом остаётся отзывчивым.
- **Долгий расчёт / много памяти** — уменьшите число точек БПФ или шаг сетки.

## Иконки
Иконки интерфейса — собственный набор SVG в `far_zone/styles/glyphs`: одна
сетка 24×24, одна толщина штриха, метафоры под задачи именно этой утилиты
(маркер-линия с «ручкой», точка на вершине лепестка, подъём кривой к опорному
уровню, сечение ДН). Готовые шрифтовые наборы такого не дают: раньше в одной
панели соседствовали FontAwesome и Material, а «нормировка» и «локальный
максимум» были двумя похожими волнами.

Цвет подставляется при отрисовке — в файлах стоит `currentColor`. Отсюда две
вещи: иконки маркеров покрашены в цвет своих линий, а у checkable-кнопок
включённое состояние горит акцентом (`app_icon(..., color_on=...)`).

Если файла глифа нет, имя уходит в `qtawesome` по таблице `ICON_ALIASES` —
запасной путь на случай неполной сборки.
